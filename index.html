Santé publique mondiale · FAO — Nations Unies

Étude de la sous-nutrition mondiale

🎯 Contexte / Besoin métier

Dans le cadre d'une mission pour la FAO, l'objectif était d'analyser les données mondiales de sous-nutrition de 2017 afin d'identifier les pays prioritaires, de quantifier le paradoxe alimentaire mondial et de proposer des recommandations ciblées.

🗄️ Données

  • Source : FAO — données mondiales 2017
  • Périmètre : 535,7 millions de personnes sous-alimentées
  • Limites : Données agrégées par pays, pas de granularité infra-nationale

⚙️ Démarche

  • Exploration et nettoyage des données (EDA)
  • Calcul des indicateurs clés : disponibilité alimentaire, taux de sous-nutrition
  • Cartographie des pays prioritaires
  • Étude approfondie du cas Thaïlande
  • Outils : Python, Pandas, Matplotlib, Seaborn

📈 Résultats & Impact

  • 535,7 millions de personnes sous-alimentées identifiées
  • La planète produit suffisamment pour nourrir 101,7% de sa population
  • 9,3 milliards de personnes pourraient être nourries avec la production actuelle
  • Cartographie des pays prioritaires livrée à la FAO

⚠️ Limites & Perspectives

  • Données 2017 uniquement — pas de suivi temporel long terme
  • Perspective : intégrer des données multi-années pour analyser les tendances
Python Pandas Matplotlib Seaborn EDA Cartographie

E-commerce & Retail · Librairie Lapage

Analyse des ventes en ligne

🎯 Contexte / Besoin métier

La Librairie Lapage souhaitait mieux comprendre ses clients en ligne et identifier les leviers de fidélisation à partir de 2 ans de données e-commerce.

🗄️ Données

  • Source : Données internes e-commerce Lapage
  • Période : 2 ans de transactions
  • Variables : Profils clients, catégories produits, montants, fréquences d'achat

⚙️ Démarche

  • Exploration et nettoyage des données (EDA)

  • Leviers de fidélisation identifiés par segment client
  • Recommandations marketing actionnables livrées

⚠️ Limites & Perspectives

  • Données limitées à 2 ans — saisonnalité à confirmer sur plus long terme
  • Perspective : mise en place d'un scoring de fidélisation automatisé

Sécurité financière · ONCFM

Détection de faux billets par ML

🎯 Contexte / Besoin métier

L'ONCFM avait besoin d'un algorithme capable de détecter automatiquement les faux billets de banque, avec un script Python directement utilisable par les équipes métier en production.

🗄️ Données

  • Volume : 1500 billets (vrais et faux) avec mesures géométriques
  • Variables : Dimensions physiques des billets
  • Qualité : Données propres, peu de valeurs manquantes

⚙️ Démarche

  • Exploration et analyse des distributions (EDA)
  • Comparaison de 3 algorithmes : Régression logistique, KNN, Random Forest
  • Sélection du meilleur modèle par validation croisée
  • Sérialisation du modèle (joblib) et création du script predict.py
  • Mise en production du script utilisable directement par les équipes

📈 Résultats & Impact

  • 99,3% de précision — 298 billets sur 300 correctement classés
  • AUC de 1,000 — discrimination parfaite
  • Modèle retenu : Régression logistique
  • Script predict.py sérialisé, mis en production

⚠️ Limites & Perspectives

  • Perspective : Créer une interface contenant l'application finale pour tester les billets avec l'algorithme choisi

🎯 Contexte / Besoin métier

Dans le cadre du déploiement réseau 4G/5G d'Orange France, les équipes avaient besoin d'une veille hebdomadaire sur les autorisations ANFR. Ce processus était réalisé manuellement via des macros Excel, source d'erreurs et chronophage. L'objectif était d'automatiser entièrement ce pipeline.

🗄️ Données

  • Source : Base de données EDR (PostgreSQL) — base interne Orange
  • Contenu : Données ANFR Orange, autorisations réseau 4G/5G sur tout le territoire français

⚙️ Démarche

  • Étape 1 — Extraction : Connexion sécurisée à PostgreSQL via psycopg2, identifiants via variables d'environnement
  • Étape 2 — Requête SQL complexe : CTE imbriquées pour filtrer les opérateurs Orange, calculer le N° COMSIS max par dossier, associer les UPR régionales
  • Étape 3 — Traitement 5G : Filtrage des systèmes 5G
  • Étape 4 — Traitement LTE : Filtrage des systèmes LTE
  • Étape 5 — Envoi automatique : Distribution aux équipes de la DOR dans le national

📈 Résultats & Impact

  • ✅ Remplacement complet de la macro Excel par un pipeline Python robuste
  • ✅ 2 fichiers Excel générés automatiquement : Veille_5G.xlsx et Veille_LTE.xlsx
  • ✅ Gain de temps significatif pour les équipes déploiement
  • ✅ Réduction des erreurs humaines liées au traitement manuel
  • ✅ Sécurisation des identifiants via variables d'environnement

🎯 Contexte / Besoin métier

L'équipe Production Réaménagement du déploiement mobile de Orange gérait le suivi des opérations entre le Go Travaux (GOT) et la Mise En Service Technique(MEST) via un fichier Excel partagé sur SharePoint. Ce fichier ne permettait pas une prise de décision rapide : pas de visualisation des prérequis manquants, pas de suivi des performances par aménageur, pas d'indicateurs de temps de coupure. L'objectif était de concevoir un tableau de bord Power BI interactif répondant aux besoins des chefs de projet.

🗄️ Données

  • Source : SharePoint Orange — fichier Excel "Pilotage GOT non MEST"
  • Contenu : Opérations réseau, prérequis, aménageurs (AXIANS, CIRCET, ENSIO, SYNECTY, SPIE), CDP Travaux, dates GOT/MEST, temps de coupure
  • Fréquence de mise à jour : 2x/jour (8h et 17h)
  • Limites : Source unique Excel — pas encore de connexion directe à une base de données

⚙️ Démarche

  • Analyse du besoin : Rédaction du cahier des charges avec les parties prenantes
  • Modélisation : Connexion Power BI au fichier SharePoint, transformation des données (Power Query)
  • Vue 1 — Portefeuille : Compteur bloquées/non bloquées, progression par taux d'avancement, tableau de suivi détaillé avec prérequis manquants
  • Vue 2 — Performance TC : % TC déclaré vs TC réel par mois, médiane des temps de coupure, suivi par aménageur
  • Vue 3 — Performance Prod & Délais : Historique GOT réalisés vs MEST par mois, médiane des délais
  • Vue 4 — Fin de chantier / Prév MEST : Suivi des dates prévisionnelles vs réelles par MOE

📈 Résultats & Impact

  • ✅ Vision sur les opérations pilotées en temps réel
  • ✅ Opérations bloquées détectées et visualisées immédiatement
  • ✅ Identification automatique des prérequis manquants par opération
  • ✅ Suivi de la performance desaménageurs (AXIANS, CIRCET, ENSIO, SYNECTY, SPIE...)
  • ✅ Visualisation du temps de coupure réel vs déclaré par mois

⚠️ Limites & Perspectives

  • Source de données unique (Excel SharePoint) — sensible aux modifications manuelles
